# HTTP API Cloute

REST API для аккаунтов, документов и ссылок доступа. Правка текста идёт не здесь, а по WebSocket (`api/protocol.md`).

## Общие правила

- Тела запросов и ответов — JSON. Запросы с телом обязаны иметь `Content-Type: application/json`, иначе `415`.
- Ошибка — `{"error": "<код>", "message": "<текст>"}`.
- **Сессия** — cookie `cloute_session`: `HttpOnly` (недоступна JavaScript), `SameSite=Lax`, `Path=/`, срок 30 дней; `Secure`, если сервер запущен с `CLOUTE_COOKIE_SECURE=true` (за HTTPS). Сервер хранит только SHA-256 токена.
- **Защита от CSRF**: изменяющий запрос (не `GET`/`HEAD`) с заголовком `Origin`, хост которого не совпадает с `Host`, отклоняется с `403`; вдобавок `SameSite=Lax` не даёт браузеру отправить cookie в кросс-сайтовом `POST`, а требование JSON исключает обычные HTML-формы.
- Документ, в котором у пользователя нет роли, для него «не существует»: `404`, а не `403`.

| Код ошибки | HTTP | Когда |
|---|---|---|
| `bad_request` | 400 / 415 | неверный JSON или поле |
| `unauthorized` | 401 | нет сессии |
| `invalid_credentials` | 401 | неверный e-mail или пароль (что именно — не сообщается) |
| `forbidden` | 403 | роль не позволяет; кросс-сайтовый запрос |
| `not_found` | 404 | нет такого объекта или нет доступа к документу |
| `unavailable` | 503 | сервер останавливается |
| `email_taken` | 409 | e-mail уже зарегистрирован |

## Аккаунты

`POST /api/register` `{"email", "name", "password"}` → `201` пользователь + cookie сессии.
E-mail приводится к нижнему регистру; имя 1–100 символов; пароль 8–72 байта (72 — предел bcrypt).

`POST /api/login` `{"email", "password"}` → `200` пользователь + cookie.

`POST /api/logout` → `204`, сессия удалена, cookie стёрта.

`GET /api/me` → `200` `{"id", "email", "name"}` или `401`.

## Документы

`GET /api/documents` → `200` `[{"id", "title", "role"}]` — документы, где у пользователя есть роль, новые первыми.

`POST /api/documents` `{"title"}` → `201` `{"id", "title", "role": "owner"}`. Пустое название — «Без названия». `id` — 26 случайных символов `[a-z2-7]`.

`GET /api/documents/{id}` → `200` `{"id", "title", "role"}` или `404`.

## Ссылки доступа

Ссылка — случайный токен (256 бит) и роль `editor`, `commenter` или `viewer`. Токен показывается один раз — при создании; сервер хранит только его хеш.

**Роль не хранится, а вычисляется:** владелец документа — `owner`; любой другой пользователь — **наивысшая роль среди неотозванных ссылок документа, которые он открывал**; если таких нет — доступа нет. Отсюда:

- открыть более слабую ссылку не понижает роль (комментатор, открывший ссылку читателя, остаётся комментатором, пока действует ссылка комментатора);
- **отзыв ссылки сразу забирает то, что она дала**: роль падает до следующей по силе действующей ссылки или доступ пропадает совсем;
- владелец от ссылок не зависит.

`POST /api/documents/{id}/links` `{"role"}` → `201` `{"id", "role", "createdAt", "token"}`. Только `owner`, иначе `403`.

`GET /api/documents/{id}/links` → `200` `[{"id", "role", "createdAt"}]` — неотозванные ссылки, без токенов. Только `owner`.

`DELETE /api/documents/{id}/links/{linkId}` → `204`. Только `owner`. Отозванная ссылка больше не работает, а роли, полученные через неё, пересчитываются немедленно. Открытые WebSocket-соединения тех, кто входил по этой ссылке, сервер закрывает («access changed»); клиент сразу переподключается и получает новую роль (веб-клиент перезагружает страницу под неё) или отказ `forbidden`.

`POST /api/links/{token}/join` → `200` `{"id", "role", "title"}` — документ и итоговая роль; `404` для неизвестной или отозванной ссылки. Веб-клиент открывает ссылки вида `/?join=<token>`.

## История версий

Версия — именованный снапшот документа. Версии хранятся всегда; откат не удаляет и не переписывает ни их, ни лог операций.

`GET /api/documents/{id}/versions` → `200` `[{"id", "name", "seq", "author", "createdAt"}]`, старые первыми. Любая роль.

`POST /api/documents/{id}/versions` `{"name"}` → `201` версия. Название 1–100 символов. Только `owner`/`editor`.

`GET /api/documents/{id}/versions/{versionId}` → `200` версия с полем `"text"` — видимый текст документа на момент версии. Любая роль.

`POST /api/documents/{id}/versions/{versionId}/restore` → `200` `{"seq"}` — номер последней операции после отката. Только `owner`/`editor`.

**Как работает откат.** Сервер вычисляет обычные CRDT-операции, которые делают видимый текст равным тексту версии, применяет их, записывает в лог и рассылает всем подключённым клиентам как обычные `ops` (`api/protocol.md`). Изменяется минимум, символы сравниваются по ID:

- видимые сейчас, но не в версии — удаляются;
- видимые в версии, но удалённые сейчас — вставляются заново копией (воскресить удалённый символ в RGA нельзя) сразу после предыдущего символа версии;
- остальные не трогаются.

Поэтому правки, сделанные одновременно с откатом клиентами, которые его ещё не получили, сохраняются и остаются там, где их сделали: их якорные символы не удалялись, если они есть в версии. Новые символы отката получают ID нового номера реплики пользователя, выполнившего откат, — по логу видно, кто откатил.
